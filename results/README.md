# Results files

Every file here is written by a module of `ladder_redshifts` or, for three, by a script. `reproduce.sh` regenerates
the fast ones, and `reproduce.sh --full` regenerates all of them except `redshift_sudoku_comparison.json`, which
needs a copy of the High-z Sudoku code, and `redshift_photoz_calibration.json`, which needs the SPT collaboration's
posted tables. [`docs/results.md`](../docs/results.md) has the tables drawn from these
files.

| File | Contents | Written by |
|---|---|---|
| `redshift_real_batch.json`, `.csv` | Real spectra under `data/spectra/` (2016.1.00672.S cube cut-outs and SPT0027-50) scored against `data/truth.csv`. For each source: engine z and confidence; `p_published` (posterior mass on the published z); verdict; the equal-weight-sum, detection-rule and naive-spacing answers; detections; candidates. | `batch_real` |
| `redshift_real_batch_admit.json`, `.csv` | The same for the ADMIT-route spectra, plus the result from the measured windows alone. | `batch_real --admit` |
| `redshift_real_SPT0027.json` | SPT0027-50 (Band 2): detections, best z and confidence for each estimator and prior, candidates, and the added-noise and reduced-coverage stress tests. | `realspec` |
| `redshift_followup_SPT0314-44.json` | Follow-up planner for SPT0314-44: candidates, the lines each one predicts, and P(confident & correct) for every Band 3–7 LO under three conditions. `unseparated` marks a candidate that a tuning cannot tell from a rival, because it adds only lines both predict. | `followup` |
| `redshift_atlas.json` | Synthetic atlas: confident-correct and confidently-wrong fractions for each setup and estimator, by S/N and by redshift; error taxonomy; calibration tables; `reliability` (how often answers above 0.95 and 0.99 are right). | `atlas` |
| `redshift_atlas_raw.npz` | Per-source raw output behind the atlas (true z, S/N, estimates, confidences); `atlas --plot-only` re-plots from it. | `atlas` |
| `redshift_traps.json` | The three rebuilt traps, for each variant and step, with the adopted (robust) and the first (narrow) [CI] prior. | `traps` |
| `redshift_traps_examples.npz` | Mean posterior per step for the figure; `traps --plot-only` re-plots from it. | `traps` |
| `redshift_tuning.json` | Tuning optimiser: greedy tuning positions and outcomes for Band 2 now, Band 2 with the upgrade, and Band 3, under two time models and two source brightnesses. Each entry has the fraction on the selection population and, under `held_out`, on an independent population. | `tuning` |
| `redshift_ambiguity.json` | HerBS-108's undertone family of solutions, the anharmonic mismatches, and the sonification mapping. | `ambiguity` |
| `redshift_noise_only.json` | The engine on spectra that contain only noise: how often the confidence exceeds 0.5, 0.8 and 0.95, with the per-line velocity tolerance and with exact line positions. | `scripts/noise_only_check.py` |
| `redshift_degradation.json` | The seven real multi-line spectra with noise added. For each source and each S/N of the second-brightest line: how often the engine and the equal-weight sum (each with no prior and with the survey prior), the detection rule and the guided rule (3σ and 4σ; 3σ with the prior) return the published redshift, a different one, or none; how often the engine's and the cross-correlation's best guess is the published redshift; the mean over sources; and every method on every real spectrum as observed. The same quantities with each source's published photometric redshift as the prior, in three versions (`photoz`, `photoz_2024`, `photoz_recal`; `guided_photoz` is the guided rule with that prior), and the guided rule in the form that does not count a missing \[CI\] line (`guided_co_only`, under every prior). `rule_family`: the settings of the rule family, the settings chosen for comparison (per prior: totals, per level, per source, record on the real spectra), the best setting at each level, and the engine at each confidence threshold with the best rule at no more wrong answers. In `as_observed`, `rule_family` gives every setting's outcome on that spectrum as one letter each (c, w or n). | `degrade` |
| `redshift_rule_family.csv` | One row per rule setting and prior (72 with no prior, 216 with the 2020 photometric prior): the four dials and the prior share, correct and wrong answers over all 5,600 noise draws and at each level, and the record on the 19 real spectra. | `degrade` |
| `redshift_sudoku_comparison.json` | The classes that the High-z Sudoku code (`RSGquality`, Bakx & Dannerbauer 2022) gives each real source at its published redshift and each atlas setup, next to this engine's results. Not regenerated by `reproduce.sh`: it needs a copy of that code. | `scripts/compare_sudoku.py` |
| `redshift_photoz.json` | Each source's published photometric redshift as its prior, on the 19 real spectra that have one. For each source and each of three versions of the prior (2020 as published, 2024 revision, 2020 recalibrated): centre, width and offset from the published z; the engine's best z, confidence, `p_published` and candidates; the guided rule and the window rule, each with a missing \[CI\] line counted (`ci_counted`) and with CO lines only (`co_only`); the rule solution the prior favours (`pick`); the cross-correlation × p(z). `summary` counts outcomes for the one-line and the multi-line sources, and under `all` gives the number of confident answers, how many were wrong, and the exact 95% upper bound on the wrong-answer rate. | `photoz` |
| `redshift_photoz_calibration.json` | How well the photometric redshifts of Reuter et al. (2020, Table F.1) match the spectroscopic ones, for all 81 SPT sources, the 60 outside this sample and the 21 in it, for the 2020 values and the 2024 revision; the shift and widening used for the recalibrated prior; the SPT0452-50 entry; SHA-256 of the two posted tables it was computed from. | `scripts/photoz_calibration.py` (needs the posted tables) |

## `independent/`: the test on 23 sources the engine was not developed on

Written by the same modules with `LADDER_REDSHIFTS_SAMPLE=independent`, in the single run of 14 November 2026
([`docs/results.md`](../docs/results.md), section 11). `reproduce.sh` does not touch this folder.

| File | Contents | Written by |
|---|---|---|
| `redshift_real_batch.json`, `.csv` | As above, for the 23 spectra of `data/independent/`. The `route` field records that they were made from the cut-outs. | `batch_real` |
| `redshift_photoz.json` | As above, for the same spectra. | `photoz` |
| `redshift_degradation.json`, `redshift_rule_family.csv` | The noise-added test on the five multi-line sources that show two lines at 5σ. `as_observed` covers all 23 sources. The rule settings named under `chosen` there are re-chosen on this sample; the two settings chosen beforehand are in `report.json`. | `scripts/independent_noise_test.py` |
| `report.json` | The outcomes fixed in the plan: confident answers and wrong ones with their bounds, counts by group, the engine against the two rule settings chosen beforehand (as observed and with noise added, per source), and one row per source. | `scripts/independent_report.py` |

To re-run from the saved spectra (the numbers are reproduced; `route` then reads "saved spectrum"):

```bash
export LADDER_REDSHIFTS_SAMPLE=independent
python -m ladder_redshifts.batch_real && python -m ladder_redshifts.photoz
python scripts/independent_noise_test.py && python scripts/independent_report.py
```
